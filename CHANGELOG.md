## [0.1.0] - 2026-11-03

The first release. Detects drift in the resources Terraform already manages, attributes it to a CloudTrail event where the evidence supports one, scores it against a rule set you can read, and recommends reverting or updating the code. It never does either.

### Added

- **`crosswind scan`** runs `plan -refresh-only` against one stack or every stack under a directory, and reports what differs from the code. Discovery skips anything that looks like a module rather than a root module, and resolves ambiguity towards scanning: a false positive costs one visible "could not check" line, a false negative is a stack nobody is checking and nobody knows it. `--exclude`, `--concurrency`, `--var-file`, `--min-severity`, `--profile`, `--role-arn`, `--region`, `--binary` and `--config`.
- **Terraform and OpenTofu, both supported and both tested.** The binary is detected automatically and identified by its own `version` output rather than its filename, because `tofu` symlinked as `terraform` is a real thing people do. `--binary` picks one. Everything Crosswind reads is identical between the two — both emit plan JSON `format_version` 1.2 and put drift in `resource_drift` — and CI runs the end-to-end suite against OpenTofu 1.13 and two Terraform versions.
- **Read-only by construction, enforced structurally.** Every Terraform invocation goes through one function with an allowlist of five subcommands (`version`, `init`, `providers`, `plan`, `show`). It is an allowlist, not a denylist, so a subcommand added by a future release is refused by default. `plan` always carries `-refresh-only`, `-lock=false` and `-input=false`, and flags that could mutate are rejected on every subcommand. [`tests/test_safety.py`](tests/test_safety.py) asserts `subprocess` is imported in exactly one module, that no `os.system`/`exec`/`popen` appears anywhere, and that no write subcommand exists as a string literal outside the wrapper that refuses it — so a second route to the same danger cannot appear without a test failing.
- **Your working tree is not written to**, verified by experiment rather than asserted. `TF_DATA_DIR` relocates `.terraform/` into a private temp directory and `init -lockfile=readonly` leaves `.terraform.lock.hcl` byte-identical. The end-to-end tests hash every file in a real stack before and after a scan. A stack with no lock file is reported as "could not check" with the one command that fixes it, rather than being locked on your behalf.
- **Plan files are treated as the secrets they are.** A plan file is the entire prior state, including everything providers store in plain text. They are written into a `0700` directory from `mkdtemp`, `chmod 0600` on arrival (Terraform writes them `0644`), never inside your stack, and deleted on return, on exception, at exit, and on `SIGINT`/`SIGTERM` — `atexit` alone is not enough, because the default `SIGTERM` disposition kills the process without running it.
- **Attribution from CloudTrail `LookupEvents`**, with the API's limits designed around rather than discovered: a shared token bucket under the ~2 req/s per-account quota, exponential backoff with full jitter so threads don't retry in lockstep, a per-run cache so one resource is one lookup, and a failure budget that stops paying for attribution once it has clearly stopped working. Read-only events are discarded, since a `Describe` call cannot have caused drift.
  - Confidence is a statement about **which evidence is present**, not a threshold on a score: `high` needs both an exact resource match and an event name the mapping associates with the attribute that drifted. A pile of weak signals cannot add up to a confident wrong answer.
  - **`unknown` names nobody.** There is no code path that produces an actor without an event, and every `unknown` carries a machine-readable reason — `no_matching_events`, `outside_cloudtrail_retention`, `unmapped_resource_type`, `lookup_denied`, `throttled` and others. Every attributed finding carries the event ID, name, time and principal exactly as CloudTrail recorded them, so a reader can go and check.
  - A CloudTrail failure degrades that finding to `unknown` and never fails the scan. Drift reporting works with no AWS credentials at all.
  - Mappings live in [`cloudtrail.yml`](src/crosswind/data/cloudtrail.yml), keyed on the Terraform resource type. Covers security groups and rules, IAM roles and policies, S3 buckets, EC2 instances, RDS instances, Lambda functions, load balancers and listeners, ECS services, autoscaling groups, KMS keys and Route 53 records, plus SQS, SNS, DynamoDB, log groups, EFS, ElastiCache, CloudFront, API Gateway, EKS and Secrets Manager. Per-resource `global: true` routes IAM, Route 53 and CloudFront lookups to `us-east-1`, which is the single most common cause of a real change attributing to nothing.
- **Severity from a rule set you can read and argue with.** [`severity.yml`](src/crosswind/data/severity.yml) holds 23 rules: public ingress on a security group is critical, an IAM policy gaining a wildcard is critical, encryption or public-access changes are high, instance and storage size changes are medium, tags are low. First match wins in file order, because a scoring system where you must know every other rule to predict the outcome is one nobody will edit. **Every finding names the rule that scored it**, in every output format.
  - Per-project overrides in `.crosswind.yml`, merged by rule id so a project can soften or sharpen a shipped rule without restating the other twenty-two.
  - The predicate vocabulary is **closed on purpose**. Crosswind loads `.crosswind.yml` from the repository it is scanning, so an expression language there would be remote code execution with extra steps. Adding a predicate is a Python change; a malicious config file can at worst mis-score a finding.
- **Ignore rules** in `.crosswindignore`, `.gitignore`-shaped because everyone already knows how that works. `crosswind scan --print-default-ignores` prints a suggested file covering drift that is expected by design — an autoscaling group's `desired_capacity`, an ECS service's `desired_count`. It is **printed, not applied and not written**: hiding findings a user never opted out of is the same failure as calling a broken stack clean. Suppressed findings are counted and the total shown, so you can tell "clean" from "quiet".
- **Four output formats**, all pure functions of one `Report` object — which is what makes the cross-format tests meaningful.
  - **Terminal**, ordered by severity, plain ASCII so it survives a CI log and a ticket.
  - **HTML**, one self-contained file with no external references and **no JavaScript at all** — collapsing comes from `<details>`, and the filtering a dashboard would add is not worth the attack surface on a file describing someone's infrastructure. Prints sensibly, and uses the same palette as Preflight's PDF because it goes to the same reader.
  - **Markdown**, sized for a PR comment and a GitHub job summary, with pipes and angle brackets escaped (attribute values genuinely contain both) and a cap that keeps it under GitHub's 1 MiB job-summary limit, which is truncated silently.
  - **JSON**, versioned (`schema_version: 1.0`) and documented in [`docs/json-schema.md`](docs/json-schema.md). Sorted keys and `null` rather than omission, so two reports of an unchanged account diff to nothing.
- **A stack that could not be checked is never reported as clean.** Every failure path — a failed `init`, a failed plan, malformed JSON, a permissions error, a timeout, a bug of ours — produces a `FAILED` result with the error attached, counted separately, rendered above the findings in every human format, and forcing exit code 2. The report is still written.
- **Exit codes**: 0 no drift at or above `--min-severity`, 1 drift found, 2 a stack could not be checked or the tool failed. 2 beats 1 — a report with a hole in it is a different situation from a report with findings in it, and the more urgent one.
- **Two layers of secret redaction**, applied once at the parser boundary so no renderer can leak what was never put in the model. Terraform's own `before_sensitive`/`after_sensitive` markers are walked in lockstep with the value, since they mirror the value's shape rather than listing names and a `true` on a parent block means everything beneath it. Name-based matching catches `password`, `token`, `secret`, `private_key` and friends regardless, because provider authors forget. `user_data` is never shown, only its length. The end-to-end tests seed two real secrets into a real stack — one marked, one not — and assert neither reaches any of the four formats.
- **`crosswind demo`** builds a report from bundled fixtures with no AWS, no credentials and no Terraform binary, through the same renderers a real scan uses. The fixture deliberately includes the unflattering cases: a stack that could not be checked, findings that attribute to `unknown` for two different reasons, a provider-marked password rendering as a placeholder, and suppressed findings. It exits 0 regardless, because a demo that fails somebody's build is a bad demo.
- **`crosswind doctor`** checks the binary, stack discovery, state access (via a real `init` in a throwaway data directory), credentials and CloudTrail access, and says which would fail — in a couple of seconds, before you wait on a real scan. Missing credentials are a warning, not a failure, and it says so: drift detection works without them.
- **Conservative cost estimates.** A figure appears only where the attribute has an unambiguous price and both values are in the static table, and every one carries a `basis` sentence someone can check with a calculator plus a note that it is an upper bound, since list price ignores Savings Plans and Reserved Instances. There is deliberately no NAT gateway price and no Lambda memory price: both need a traffic volume we would have to invent.
- **Composite GitHub Action** with OIDC, job summaries and report artifacts. `fail-on-drift: false` for a scheduled scan that should report without going red — a check that fails every morning is one people mute — while a stack that could not be *checked* always fails the job. A scheduled example with a per-environment matrix is in [`examples/workflows/scheduled-drift-check.yml`](examples/workflows/scheduled-drift-check.yml).
- **IAM role template** ([`iam/role.cfn.yaml`](iam/role.cfn.yaml)) and flat policy ([`iam/policy.json`](iam/policy.json)), split into three managed policies by size: CloudTrail and identity (two actions, the only calls Crosswind itself makes), state read (scoped to one bucket and one key, with `kms:Decrypt` and deliberately no `kms:Encrypt`), and refresh (broad, and optional). The OIDC trust policy pins to a branch rather than `repo:owner/repo:*`. [`tests/test_policy.py`](tests/test_policy.py) fails the build on any action that is not `Get`/`List`/`Describe` plus two documented exceptions.
- **Docker image** running as uid 1000 rather than root, with a Terraform-compatible binary baked in.
- Docs: [`docs/design.md`](docs/design.md), [`docs/installation.md`](docs/installation.md), [`docs/configuration.md`](docs/configuration.md), [`docs/github-actions.md`](docs/github-actions.md), [`docs/json-schema.md`](docs/json-schema.md), [`docs/attribution.md`](docs/attribution.md), [`docs/severity-rules.md`](docs/severity-rules.md), [`docs/threat-model.md`](docs/threat-model.md), and [`iam/README.md`](iam/README.md) for the permissions tradeoff.

### Notes

Things worth knowing before you rely on this, each of which is also in the README's limitations:

- **Only resources Terraform already manages are checked.** Crosswind compares state to reality, so a resource created in the console that Terraform has never known about is invisible to it. Discovering unmanaged resources is a different problem and is not in v1 — a bad version of it produces a long list of things that are fine.
- **Attribution is bounded by CloudTrail.** Management events only, so a data-plane change is not recorded. Ninety days of history. Events take up to about 15 minutes to appear, so drift created moments before a scan may legitimately attribute to `unknown`.
- **AWS is the only cloud with attribution.** Drift detection works for any provider Terraform can refresh; the "who" is AWS-only.
- **Read-only ultimately depends on your credentials.** The design makes Crosswind unable to issue a write and the tests enforce it, but `terraform plan` evaluates your configuration and runs your providers — including an `external` data source, which executes a program. Crosswind cannot sandbox that. Scan only code you trust, with read-only credentials.
- **The `local` provider reports a modified file as deleted, not updated**, because its `Read` compares a checksum and drops the resource from state on a mismatch. This is why the end-to-end tests assert a `deleted` kind for an edited file, and why the `update` change shape is validated against output captured from a real plan instead. A test pins the behaviour so a provider change is noticed.
- **A set-typed attribute can read as drift when nothing changed.** Providers return set elements in arbitrary order and Crosswind diffs by position, so a reordered `cidr_blocks` can appear as a change. `.crosswindignore` is the workaround. Hashing elements instead would make the attribute path meaningless to a reader, and refusing to descend would turn every security group rule change into `(4 items) -> (4 items)`.
- **HashiCorp's registry and release servers are geo-restricted** under their trade controls, and return an error page rather than a download in the affected regions. This is not a Crosswind limitation but it is fatal to using Terraform there at all — `registry.terraform.io` serves no providers, so a stack cannot be initialised. OpenTofu has no such restriction, which is why the Docker image ships it by default.
- **Cost prices are a static table** in [`cost.yml`](src/crosswind/data/cost.yml), carrying the date it was last checked. **Re-check it against AWS's pricing pages before cutting a release.** Fetching live prices would mean a network call in CI for a number that only ever needs to be approximately right.
- Tested on Python 3.11, 3.12 and 3.13, and the classifiers say so.
- Not published to PyPI yet, so `pipx install crosswind` does not work for this version. Install from a checkout or use the container image.
